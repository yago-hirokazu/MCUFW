# 引用変数展開で不要な空白が挿入される問題

更新日: 2026-10-22

現行exe.cのexpand_quoted_argとtest12.sh・answer_test12_sh.txtに対応する修正記録。
以下の確認結果は当時のもの。今回の文書整備では試験を再実行していない。

## 補足

- `test_exe.exe`: `/MCUFW/src/core/esh/test/exe/test_exe.exe`
- `test12.sh`: `/MCUFW/src/core/esh/test/exe/test12.sh`


## 背景

下記の`test12.sh`シェルスクリプトを`test_exe.exe`で実行したときに、課題に気づいた。

```bash
#!/bin/sh

k=0
while [ $k -ne 3 ]; do
	k=`expr $k + 1`
	echo 'outer'
	echo "k=$k"

	l=0
	while [ $l -ne 3 ]; do
		l=`expr $l + 1`
		echo 'inner'
		echo "l=$l"

		if [ $l -eq 2 ]; then
			echo 'break 2'
			break $l
		fi
	done

	echo 'not reached'
done

echo 'after loops'
```

## 課題

`echo "k=$k"` が `k = 1` と表示される。
`echo "l=$l"` が `l = 1` と表示される。
`=`の前後にスクリプトでは空白が入っていないが、実際に表示されたときに空白が入っている。

## 調査結果

`tty.c` の入力取り込み処理が二重引用符の内外を区別せず、`=` を独立した
トークンにするための空白を前後へ挿入していた。また、二重引用符自体は字句解析へ
渡されていなかった。

このため、次の1引数として解釈すべき記述が、字句解析前に3引数へ変化していた。

```text
"k=$k" -> k, =, $k
```

`echo` は複数の引数間へ空白を出力するため、結果が `k = 1` となっていた。

## 対応

- 入力取り込み処理で二重引用符の状態を保持し、引用符内の `=` を分割しない。
- 二重引用符で囲まれたコマンド引数を1個のトークンおよびバイトコードとして扱う。
- 引用付き引数をコマンド実行時に展開し、リテラル部分と変数値を1個の引数へ格納する。
- `test12.sh` の出力を検証する回帰テストを追加する。

## 確認結果

`test12.sh` のコマンド出力は次のとおりとなった。

```text
outer
k=1
inner
l=1
inner
l=2
break 2
after loops
```

既存の `test1.sh` から `test10.sh` までのゴールデンテストもすべて成功した。
